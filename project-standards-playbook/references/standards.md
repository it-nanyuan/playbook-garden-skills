# 项目设计与开发统一标准

版本 1.0 · 2026-10-18

适用于新建软件产品、界面设计、组件体系和对应实现。先明确业务目标、产品类型和交付阶段，再应用有关条款。既有项目的局部维护按影响范围执行；硬件、空间设计等采用专项规则。端差异见 [专项规则](platform-profiles.md)，取舍依据见 [来源](evidence.md)。

## 一 规则层级与使用方式

| 层级 | 使用方式 |
| --- | --- |
| 当前任务和用户已确认规则 | 决定本次目标、范围和可执行动作；资料中的旧指令不改变当前授权 |
| 跨项目基线 | 每个适用项目遵循，下列 R01—R24 按场景执行 |
| 端或产品专项 | 规定导航、密度、交互和领域差异，不能扩张到无关产品 |
| 项目参数合同 | 登记已确认的颜色、字体、间距、组件和版本，设计与实现都按此执行 |
| 默认建议与待审方案 | 补足未决定事项；默认值需适配产品，待审稿保持待审 |

跨项目统一的是规则、语义、复用和验收方式。不同产品可以有不同品牌、密度和尺寸。旧归档、示例数值、工具默认值不覆盖已确认的当前方案。

## 二 项目组织与需求

### R01 项目身份稳定

正式项目名使用小写英文 kebab-case，同一产品的不同端放在同一根目录；README、仓库映射、设计标题与交付前缀一致。UI 目录具体命名执行 `/Users/NAN/UI/project-naming-rules.md`；包名、应用 ID、品牌展示名按技术与品牌要求独立登记。规范更新不自动触发历史项目更名。

### R02 启动先形成最小项目合同

明确目标用户、核心任务、完整业务链路、平台、当前阶段、交付物和验收条件。已有材料足够时直接推进；缺失信息会改变当前方案才提问。产品需求、UI 设计、客户端、服务端和发行分别记录完成度。

建议按用途组织 `requirements/`、`design/`、`docs/`、`work/`、`outputs/`；保留既有仓库结构，不为目录整齐迁移运行工程。README 指向当前入口、运行方式与未完成项。

### R03 按完整链路推进

维护功能总表，覆盖入口、输入、确认、执行、结果、返回、重新进入与异常恢复。先完成一条有价值的用户链路，再扩展模块；界面存在、按钮可点击和原型连线数量不能代表功能完成。纯设计阶段记录业务事件与接入边界。

## 三 设计源和公共复用

### R04 先有可查看设计，再按稿实现

界面新建或明显改版先产出可查看的设计和主要状态，开发读取对应设计上下文、截图、组件及参数；完成后对照运行截图。只调整已有明确设计的局部缺陷，可直接依据现有源修复。设计工具受阻时保留缺口，不能默认为自由重画。

### R05 公共库按功能组织

新 Figma 设计优先检查 `shared-design`；按基础、前台、后台、公共功能、业务扩展与资产组织，Tabbar 等同类组件保持统一入口。项目组件维护业务特性，不把各项目所有组件堆进公共库。

重复导航、按钮、输入、选择、列表、状态、弹窗等采用真实主组件与实例；设计稿不能仅复制外观。代码按“公共基础库 → 项目主题与展示封装 → 功能局部组件”复用。设计实例关系和代码复用分别验证。

### R06 公共能力与业务隔离

公共展示组件接收展示模型、配置和回调；不持有业务 API、路由、权限、仓库或服务定位器。应用负责业务和装配。已发布代码包使用明确版本或标签；不靠相邻源码别名绕过版本边界。

已有组件能力不足时，先判断是项目特例还是通用缺口。项目特例放 facade；通用能力经兼容评估补公共库、在授权范围内发布并验证消费方。不得为一个项目修改共享默认值，影响其他项目。

### R07 组件修改验传播

检查主组件变更能传播，实例文字、图标、业务状态覆盖仍独立；检查浅深色、选中/未选、禁用/忙态与实际页面实例。不能只修当前页面的偏移量，留下同类实例继续出错。

### R08 当前源与归档分明

登记设计文件、节点、版本/日期、图稿、路由和代码组件映射。保留已建立的页面编号和跳转目标，替代稿移入归档并标注。当前设计、运行实现和离线包可以有时间差，须记录差异；旧 `.fig`、PDF、截图不冒充当前全量源。

Figma 新项目默认有独立封面并设为文件缩略图，包含项目名、产品说明、代表页面，沿用公共封面结构并保留产品品牌。交付范围需要时导出 PNG、PDF 或备份；工具未成功生成的文件不能标成已交付。

## 四 布局 文字与组件几何

### R09 任务优先与信息密度

常规手机页面和工作台采用紧凑标题、连续分组、清楚主次和贴近任务的操作；避免大标题、解释段落、重复上下文和无用途留白。卡片用于完整对象或有边界的任务，避免层层套卡片。密度不能以缩小字体和压缩点击区换取；营销与展示页面可有相应视觉节奏。

### R10 间距由语义与唯一所有者控制

先定义页面外边距、模块间距、关联内容、字段、操作、卡片内距和分隔线 token。父容器负责相邻实际可见模块的外间距，子组件负责自身内距；不要重复叠 margin/padding，隐藏模块同步去掉空占位，末项不带多余尾距。

无既定参数的新手机项目，可从模块 16、关联内容/按钮 8、卡片内距 16 开始评估；这些是起点。页面边距、连续列表、聊天元数据、媒体拼图、沉浸舞台和系统安全区分别定义，禁止全局替换裸数字。

### R11 对齐落实到父内容区

先确定父容器可用边界、中轴与基线。结果图标、标题、说明作为整体共轴；单个窄主按钮同轴，撑满按钮左右等距。左标题/右关闭是独立组，表单保持阅读方向对齐，标准右侧操作组按其语义处理。

同排输入、下拉、按钮测实际边框高度和顶线；账号、右值、箭头对齐实际内容边界。布局用约束和 token，不用一次性偏移补丁。区分 layout box、可见字形、图标内层几何和点击区，按逻辑单位测量，不把截图物理像素当布局值。

### R12 文字按角色定义

定义导航、区块、正文、列表标题、值、说明、按钮、元数据和代码的字体、实际字重、字号、行高与颜色；绑定样式并使用相应字体文件及中文 fallback。选中不要无故加粗；同角色不逐页漂移，不能把所有合法用途压成同一字号。

输入占位、实际值、禁用、错误有清楚差异；placeholder 不写入真实值。长文自然增高，单位保留独立空间；允许系统文字放大，不靠关闭缩放解决溢出。字体与密度按移动、桌面和品牌分别确定。

### R13 图标统一实际视觉

同角色图标统一来源、实际线宽、端点/转角、视觉尺寸与光学居中；分尺寸维护。检查内层路径、继承缩放和裁切，不能只改外框。选中图标与标签的状态色/强调一致。点击区独立于图形，不能为缩图标缩掉命中范围。

图像可用于插画、照片和业务资产；文字、按钮、表单、导航保持原生可编辑。保留素材来源、许可及与业务语义的对应，不能用整页截图拼出“可编辑 UI”。

### R14 表单和列表遵循家族合同

单行文本、搜索、密码、选择在同一产品和密度下统一实际边框高，多行输入独立定义。外标签、说明、错误各有固定语义位置，支持文本放大。不要把说明伪装成另一列字段；按内容与操作分组。

功能行、实体行分别定义共享档位，不逐行随意设置高度；同一家族空摘要不应产生偶然高度变化。长内容是否换行按角色统一，截断数据保留全文路径。分组列表只在实际可见条目之间画分隔线，单条和末项无收尾线；数据表网格按专项合同处理。

### R15 空态整体居中且可恢复

插图/图标、标题、说明和必要动作作为一组，在扣除导航、搜索、工具栏和固定操作后的可用区水平与垂直居中；短窗口、键盘、大字时允许滚动，不能用固定空白高度伪装中心。

按场景使用有语义的视觉；尺寸由主区/窄侧栏/手机角色确定。空数据、无搜索结果、未选择、未连接、首次加载和失败分别呈现。有旧数据时加载与失败保留旧数据和反馈，不以空态掩盖错误。动作必须真实可用。

### R16 弹层统一层级与操作

同产品菜单、选择器、tooltip、dialog、sheet 共用组件与密度；桌面不照搬移动 Material 大气泡。提示和错误有适度背景、图标、内距和可执行下一步，避免悬空红字；普通后台页不长期堆解释横幅。

锚定菜单默认在触发器附近且不遮挡它，随内容定尺寸，空间不足翻转并限高滚动；选择器菜单可至少匹配触发器宽度。有箭头时箭头与底板连续。弹窗正文可增高/滚动，动作可见；双操作等视觉尺寸，危险操作明显，安全操作优先焦点。结果居中与表单左对齐不要混淆；未保存和有后果操作按业务风险确认，普通直接操作不重复确认。

### R17 响应式与系统区域

手机至少检查正常与窄屏代表尺寸、长文本和大字；以内容决定断点。390×844 和 320 宽是现有手机项目常用检查样本，不是所有设备的唯一尺寸。桌面检查最小窗口、缩放与多栏收缩。

安全区和键盘占位由明确一层负责，避免重复计算；运行应用使用真实系统区域，不画假的状态栏和键盘。悬浮底栏按实际测量高度预留内容区；不把设计稿底部 34/50 等参考值写死。固定操作不能遮住最后内容。

### R18 主题 语言与交互反馈

浅深色使用语义 token，分隔线、控件边线和表格线可分别调整，不能改一个色值牵动全部。支持主题的产品须检查全部文字层级与状态，避免暗色继承黑字；国际化检查长文与混排。

保留有意义的选中、禁用、忙态、键盘焦点和悬停。iPhone/iPad 遵循已确认的无灰色遮罩/水波纹偏好，不删除键盘焦点或选择语义。动效支持定位与连续性，兼顾减少动态设置；各端导航规则见专项。

## 五 工程与真实业务状态

### R19 按职责和依赖方向分层

应用壳负责环境、路由和依赖装配；功能层处理业务交互；展示层负责 UI；领域契约描述能力与结果；适配器隔离供应商 SDK、网络、设备和存储。页面不堆请求、权限、数据转换和全部布局，功能模块不互导页面。

领域契约不携带 UI/SDK 类型。按项目现有栈组织，不把 GetX、go_router、Melos 或 Rust 当跨语言统一要求。注释解释公共能力、业务语义、状态值、单位、空值、副作用和生命周期；不重复显然代码。SQL、接口和技术细则由相应领域 playbook 约束。

### R20 状态真实并有恢复路径

适用功能定义 loading、empty、error、disabled、busy、success、offline、permission-denied、cancelled 等实际分支。写入还区分未开始、进行中、结果未知与已完成；取消请求不等于远端已撤销。

保留 HTTP 状态、业务码、message、traceId 和原因；不要吞错或自动回到演示数据。fixture、离线演示、权益预览显式配置并隔离真实权益/数据。未配置能力显示不可用，原型价格和时限不直接变生产规则；会员验真失败不解锁真实权益。

### R21 生命周期与持久化可解释

稳定 ID 管理工作标签、会话、任务和列表选择；切换/重排不丢草稿、焦点、滚动或错误关联。明确资源所有者，释放订阅、连接与任务，迟到响应不得污染新状态。并发操作防重复提交，写入重试满足幂等或显式重核条件，未知结果先核查。

保存、通知、窗口关闭可分阶段；保存已成功后，后续反馈重试不能重复创建。恢复布局或草稿不重放写操作。持久化迁移保留兼容与恢复途径，凭据不进入普通配置、日志或交付样例。

## 六 验收与持续维护

### R22 证据分层记录

| 层次 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| 设计结构检查 | 原生图层、组件实例、布局约束、目标有效 | 实际点击、运行界面或用户认可 |
| 原型实际点击 | 被执行的路径、返回、取消和示例状态 | 任意输入、持久化、真实服务 |
| 静态/自动检查 | 类型、格式、边界与已覆盖逻辑 | 原生编译、视觉和设备能力 |
| 目标平台原生构建 | 依赖、插件、桥接与产物可编译 | 实际设备操作、权限、性能 |
| 运行截图与交互 | 本平台已检查状态的几何与操作 | 其他平台、真实供应商或全部功能 |
| 真实接口/设备/现场 | 已执行链路及当时环境下的结果 | 未执行平台、生产发行或长期效果 |

报告给出实际执行范围、结果、证据和未验项，不用“全部正常”代替覆盖范围。纯设计交付止于有关设计证据；实现交付验证受影响平台，不强迫无关任务跑完整套流程。

### R23 先复现再修复 同例复验

UI 缺陷建立包含页面、状态、预期、实际、根因、所有者与证据的统一清单。修复公共层后检查受影响实例，覆盖默认、异常、长文、窄屏、大字、主题与动态内容。几何判断同时看运行图和可测布局，不只看无 overflow。

涉及原生客户端时，实际解析依赖并构建受影响目标；依赖/生成配置变化后重验，不能引用变更前的通过日志。Web、widget 和模拟器不能替代其他原生平台或真机权限。完整体验版采用产品、UI、QA 三个视角交叉复核；不因此默认启动多代理或接管用户设备。

### R24 标准在复用中更新

新增可复用规则记录来源、适用范围、状态、日期及替代关系；一个项目的个例先留专项。用户反复指出同类问题时，修规范源、组件和相关 skill，并同步实际安装版及验证一致性。持久偏好进入项目记忆，规范细则仍集中维护，不复制成多份互相漂移的全文。

启动时用 [模板](project-start-template.md) 固定本项目参数；以后维护按已记录版本评估，不把新版标准自动变成全项目重构任务。
