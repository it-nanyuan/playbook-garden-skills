# 新项目启动与执行模板

复制本模板时按任务规模删减；从现有材料填写，未决定处写“待确定”并说明影响。不为填写模板要求用户重复已给信息。纯设计项目不提前初始化工程或部署。

## 项目身份与目标

| 项目项 | 本项目内容 |
| --- | --- |
| 正式名称、展示名、根目录 | 待填写；检查 kebab-case 和重名，品牌展示名独立 |
| 目标用户与核心任务 | 待填写 |
| 完整主链路 | 入口 → 输入/选择 → 执行 → 结果 → 返回/重新进入 |
| 当前阶段与本轮交付物 | 需求 / 设计 / 原型 / 开发 / 联调 / 发行中实际涉及的阶段 |
| 平台、语言、主题、设备范围 | 待填写；按端分别列出 |
| 本轮边界与外部依赖 | 待填写；付费、设备、服务配置等只列与任务有关项 |
| 标准版本 | project-standards-playbook 1.0；有更新时记录采用版本 |
| 采用的专项与领域 skill | 待填写 |

## 功能与状态总表

| 功能/页面 | 入口与返回 | 核心动作/数据 | 所需异常与恢复 | 设计状态 | 实现状态 | 证据 |
| --- | --- | --- | --- | --- | --- | --- |

## 工程合同

- 现有/选定技术栈与目标平台；不因模板强换框架。
- 页面、状态、展示组件、契约、适配器和装配入口的责任。
- API/设备/存储数据来源、错误模型、取消/幂等与资源所有者。
- 可靠持久化、迁移和草稿策略；预览 fixture 与真实模式隔离。
- 工具链、依赖锁定和受影响平台构建入口；明确真实执行后才填“通过”。

## 验收矩阵

| 检查范围 | 场景/平台 | 通过条件 | 实际执行与结果 | 证据/未验原因 |
| --- | --- | --- | --- | --- |
| 设计结构与组件 | 组件及实际实例 | 复用传播、覆盖值独立、无误连/溢出 | 待执行 | 待填写 |
| 原型点击 | 主链路及适用异常 | 入口/返回/取消/结果重入连贯 | 待执行 | 待填写 |
| 运行视觉与交互 | 各端代表尺寸、长文、大字、主题、键盘 | 对照当前稿；边界/中轴/基线/命中区正确 | 待执行 | 待填写 |
| 自动检查 | 受影响包/模块 | 相关格式、类型、边界和有意义测试 | 待执行 | 待填写 |
| 原生构建 | 受影响平台 | 最新依赖配置下实际构建成功 | 待执行 | 待填写 |
| 真实业务服务 | 适用关键链路 | 真请求/持久化/错误与恢复 | 待执行 | 待填写 |
| 真机/外部/现场 | 适用设备或环境 | 真实能力及边界验证 | 待执行 | 待填写 |

纯设计任务将实现类检查标“本阶段不适用”，不伪填通过；完整体验版从产品、UI、QA三个视角复核。不因采用三个视角默认启动子代理。
