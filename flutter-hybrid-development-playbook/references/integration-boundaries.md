# Flutter Integration Boundaries

## External Services

- 为网络和第三方 SDK 定义项目拥有的接口与领域模型，让 feature 只依赖该接口。
- 在 app 组合层注入具体实现；供应商请求、响应、回调类型和密钥配置留在适配层。
- 用 fake 适配器验证状态和错误分支。真实服务链路另做运行中请求验证，保留 HTTP 状态、业务码、message、traceId 和降级原因；不要把静默 fixture 回退当成功。

## Shared Packages

- 共享领域契约、基础能力、设计组件和业务 feature 分属清晰边界；不要让设计包依赖业务路由或后端 API。
- 消费已发布包时锁定版本并核对依赖兼容性。确需同步修改共享包时，在其源仓库验证、发布后再升级消费方。
- 相同控件的呈现、主题、反馈和无障碍语义放在共享包；选择、上传、导航和其他业务状态留在页面或 feature。
- 组件展示应用应包含可操作的状态示例，区分局部非阻塞 loading 与阻塞式 HUD 等不同反馈语义。

## Verification

- 静态分析与单测后，针对改动过的关键路径运行应用并检查真实界面及交互。
- 修改原生插件或注册流程后冷启动验证；模拟器结果与真机权限、供应商凭据、公网链路分别报告。
