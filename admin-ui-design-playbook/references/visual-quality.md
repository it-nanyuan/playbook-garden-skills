# Visual Quality

## Core Standard

目标是“专业、克制、可信、可商用”，不是“热闹、显眼、像概念图”。

## Typography

- 页面标题克制，不要满屏都是超大标题
- 一个页面通常只需要一个主标题
- 副标题和辅助说明尽量短
- 用字体层级解决信息关系，不靠堆字数

## Cards

- 卡片只在真正需要分组时使用
- 不要把每一小块信息都包成卡片
- 同一页面卡片样式数量要少
- 卡片内优先放关键指标、关键动作、清晰摘要

## Text

- 后台界面避免长段解释文字
- 提示文案只在能减少误操作时出现
- 优先让结构自己说话，而不是靠说明文字补救

## Color And Emphasis

- 颜色优先服务状态和层级，不是装饰
- 一个页面的主强调色要收敛
- 风险、警告、成功、处理中状态要稳定一致

## Mobile Enterprise Operations

适用于企业移动 App、MES / ERP、仓储、物流、路径、排程、生产管控和工业工作台页面。

- 优先采用蓝白高密度运营风格：强蓝色顶栏承载导航和产品识别，白色内容面承载指标、图表、列表、地图和操作
- 顶部保留真实状态与任务入口，例如返回、筛选、搜索、通知、日期、当前区域或当前任务，不用大标题和宣传副标题占据首屏
- 指标区可以用轻量卡片或分隔网格，但要控制半径、阴影和数量；指标必须包含单位、趋势、状态或可操作上下文
- 图表、地图、排程表、进度步骤、路径节点和任务列表应成为页面主体，避免只堆静态摘要
- 状态色要稳定映射：蓝色表示主导航、当前任务和主要行动；绿色表示正常、完成、推荐或安全；橙色表示预警、处理中或中风险；红色表示异常、高风险、阻塞或失败；灰色表示空闲、未开始、禁用或辅助信息
- 底部 tab、固定主按钮、筛选条、步骤条和列表操作要贴近真实工作流，减少跳转和解释文案
- 背景保持浅灰或白色，分隔线细，留白紧凑但可读；不要使用装饰性大渐变、背景海报、概念插画或稀疏展示板

## Spacing

- 间距要形成系统，不要一块紧一块松
- 页面块级节奏、表单控件间距、表格上下关系要统一
- 留白是为了建立秩序，不是为了显得“高级”

## Alignment And Geometry

### 对齐约束

1. 明确相对谁对齐：页面可用区、卡片内容区、弹窗正文区和标题栏分别有自己的边界。标题栏可左标题/右关闭；结果图标、标题、说明作为一个整体在正文可用区居中，不能分别参照不同容器。固定页脚、键盘和安全区须先从可用区中扣除。
2. 设父内容区左边为 `L`、宽为 `W`、水平中心为 `C = L + W/2`。窄按钮宽为 `B` 时，其左边为 `C - B/2`；撑满按钮左右沿同一内容边界。不要做成“正文居中、窄按钮从左侧内边距开始”，导致按钮整体偏左。
3. 对居中组检查 `abs(child.centerX - C)`；对撑满控件检查左右内边距差。默认只容许布局舍入带来的约 `1` 个逻辑单位误差，导出像素先按倍率还原。图标光学微调须在组件内有统一依据，不能用来掩盖整个按钮或内容组的偏移。
4. 同排输入框、选择器、按钮按相同角色的实际边框高度/顶部或基线对齐；图标与文字按组件规则垂直居中。不要用透明占位、文字空格、负边距或逐实例补丁凑齐。
5. 同类内容共用内边距和 gap token，内部间距与模块间距分开定义。容器随文案与控件自然增高，避免无依据的固定大宽高；已确认的固定页脚或全屏居中结构继续按其设计约束执行。

### 结果弹窗反例

“反馈已提交”一类结果弹窗：允许顶部标题左对齐、关闭按钮右对齐；正文图标/结果标题/说明共用正文中轴。下方仅一个“完成”按钮时，要么在该中轴居中，要么沿对称内容边距撑满。不能让正文在弹窗中间，按钮却偏向左侧；也不应对所有弹窗强制使用同一个宽高或单一按钮排布。

### 交付检查

- 对实际导出稿/运行画面检查正常宽度、窄窗口或小屏，以及长文案/大字状态；先确认截图已完成绘制，文字与按钮完整可见，再作视觉结论。
- 保留简短实测记录：父内容边界、预期中轴、按钮中心/两侧边距、采用的间距 token、截图尺寸/倍率；截图坐标不能直接冒充设计逻辑尺寸。
- 把同一种组件的主组件和实际调用实例一起检查；修好共享约束后复查结果态、空态、错误态及相关按钮，不能只修当前截图里的一个实例。
- 没有视觉材料或未运行界面时，明确标为未验证，不用静态检查通过代替对齐验收。

## Anti-Patterns

- 大标题配大段说明
- 卡片墙
- 背景、渐变、阴影全部抢内容
- 操作按钮分布零散
- 图标很多但语义很弱
- 每个模块都想当视觉中心
- 企业移动业务页面被做成营销页、概念稿或宽松展示卡片，缺少真实筛选、图表、状态、路径、进度和动作
