# 发布检查清单模板

运维与发布类交付默认尽量使用下面这类结构，确保发布、回滚和巡检可落地：

1. 变更目标
2. 发布环境与时间窗口
3. 前置检查
4. 发布步骤
5. 回滚方案
6. 发布后巡检项
7. 风险与跟进项

示例骨架：

```text
变更目标：
发布点餐系统 v1.3.0，包含支付回调修复与菜单缓存优化。

发布环境与窗口：
生产环境，2026-06-23 23:00-23:30

前置检查：
1. 镜像已推送至 Harbor
2. 数据库脚本已在预发验证
3. 回滚镜像 tag 已确认
4. 监控面板与告警通道正常

发布步骤：
1. 更新 Helm values 中的镜像 tag
2. 执行 Helm upgrade
3. 观察 Pod 滚动状态和探针结果

回滚方案：
1. Helm rollback 到上一版本
2. 如涉及配置变更，同步恢复上一版 values

发布后巡检项：
1. 首页接口 5xx 是否异常
2. 支付回调链路是否成功
3. CPU / 内存 / 错误率是否突增

风险与跟进项：
支付高峰期需重点关注订单状态延迟告警。
```
