# Project Memory Playbook

Use these instructions when a task should respect durable project memory.

## Workflow

1. Ensure the private `it-nanyuan/project-memory` repository exists locally.
2. Pull the latest memory before making project decisions.
3. Read global preferences, habits, development memory, dated decisions, and matching project notes.
4. Read design-style memory for UI, UX, website, app, product, game, slide, or image work.
5. If habits are sparse or the user says preferences are not understood, follow `references/habit-calibration.md`.
6. Apply memory while keeping the main task focused.
7. Update memory only for durable, reusable preferences or conventions.
8. If memory changed during the task, commit and push the memory repository before finishing.

## Rules

- Keep memory concise, dated when useful, and easy to scan.
- Prefer updating existing sections over creating duplicate notes.
- Keep memory commits separate from unrelated project changes.
- Do not leave updated memory local-only unless network or GitHub auth blocks the push; report that state clearly.
- Do not store secrets, tokens, credentials, recovery information, noisy logs, or temporary scratch notes.
