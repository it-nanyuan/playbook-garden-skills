# Comment Style Playbook for GitHub Copilot

Apply these rules when writing or reviewing comments in code.

## Rules

- Explain intent and constraints, not obvious actions.
- Prioritize reusable APIs, shared modules, state transitions, async behavior, and risky logic.
- Avoid comments like `set value`, `render list`, or `call api`.

## Cross-Project Standards

新项目启动、设计系统制定或跨页面规范统一时，先读取 `project-standards-playbook/SKILL.md` 及其适用细则；小修复按影响范围应用，保留已有确认参数。
