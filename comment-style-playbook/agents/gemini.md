# Comment Style Playbook for Gemini

Use these instructions when applying code comment standards.

## Rules

- Write comments for responsibility, boundaries, side effects, async behavior, and business meaning.
- Do not write comments that only describe obvious code actions.
- Prioritize shared APIs, reusable modules, complex logic, and stateful flows.

## Cross-Project Standards

新项目启动、设计系统制定或跨页面规范统一时，先读取 `project-standards-playbook/SKILL.md` 及其适用细则；小修复按影响范围应用，保留已有确认参数。
