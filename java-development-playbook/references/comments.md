# Comments

## Goal

项目重要的不只是把接口写出来，更重要的是后续别人能看懂、敢改、能排障。

## Required

- 类注释：写职责和适用场景
- Service 接口方法注释：写业务契约、参数约束、返回语义、事务、副作用和异常
- 实现方法仅在存在非显然策略、兼容或补偿逻辑时补充说明，不机械复制接口注释
- 字段注释：写业务含义、单位、状态枚举语义、特殊约束

## Priorities

- Controller 暴露接口
- Service 核心业务
- MQ 消费者
- 定时任务
- ES 同步逻辑
- 缓存更新逻辑

## Avoid

- `// query list`
- `// save data`
- `// update status`
- “负责处理相关业务”“对应某某用例”这类可套用到任何类的模板注释
- 给每个 getter、setter、显然赋值和框架样板代码补注释

## Good Bias

- 重点写业务规则和边界，不写表面动作
- 复杂分支、兜底逻辑、兼容逻辑附近可补短注释
- 注释质量优先于覆盖数量；无法提供额外信息时不要为了门禁写废话
